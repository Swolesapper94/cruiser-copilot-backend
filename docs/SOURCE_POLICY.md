# Source policy

Cruiser Copilot is only as trustworthy as its sources, so the rules about them
are stricter than the rules about anything else in the system.

## 1. Nothing is shipped

This repository contains **no** Toyota manuals, bulletins, diagrams, part
numbers or specification values. The bundled library in
`src/lib/retrieval/seed-sources.ts` is scaffolding:

- Every document is `isPlaceholder: true`.
- Every specification value is a literal placeholder string
  (`PLACEHOLDER_SPEC_A — value pending verified OEM import`).
- `SOURCE_LIBRARY_IS_PLACEHOLDER` is exported and the API raises a permanent
  caution gate while it is true.

The placeholders exist to exercise the conflict, applicability and locking
machinery — not to stand in for real data.

## 2. Authority order

| Level | Source type | Meaning |
| --- | --- | --- |
| 1 | `service_bulletin` | Manufacturer bulletin superseding earlier text |
| 2 | `oem_manual` | Factory repair manual |
| 3 | `oem_technical` | Other factory technical material |
| 4 | `verified_case` | Documented case with a confirmed outcome |
| 5 | `technician` | Named professional technician material |
| 6 | `forum` | Community forum content |
| 7 | `general` | Anything else |

Levels 1–3 are OEM. Everything else is community or third party.

`mayOverrideSpecification(candidate, incumbent)` returns true only when the
candidate has a strictly stronger authority level. **Community content can never
override an applicable factory specification.** It may add context, caveats and
real-world observations, and it is delivered under its own citation grouping
with an explicit "not a Toyota instruction" label.

## 3. Applicability gates everything

A passage is only usable once its constraints (model codes, engine codes,
markets, pump models, year range) have been compared against the vehicle:

- `applicable` — every constrained field is known and matches.
- `not-applicable` — a known field contradicts the passage. Excluded entirely.
- `unresolved` — a constrained field is still unknown on the vehicle. The
  passage may be shown as context, but it can never be treated as the
  specification.

## 4. Conflict handling

When two or more distinct values survive for the same
`specificationSubject`, a `SourceConflict` is produced. It lists every
alternative with its value, its citation and a plain summary of what it applies
to, plus the vehicle fields that would settle the question.

A conflict resolves only when exactly one alternative is fully applicable **and**
it sits at the highest authority level present. Until then the specification is
**locked**: no value is selected, no value is returned by the API, and any
measurement that would need it is stored as uninterpreted.

## 5. Citations

Citation IDs are derived from immutable passage IDs (`cit-${passage.id}`). They
are never generated by a model. Any citation ID returned by a model that was not
supplied to it is treated as fabrication and the whole model response is
discarded (see `src/lib/ai/guards.ts`).

## 6. Importing your own sources

`services/ingestion/` accepts documents **you are licensed to use**. It writes to
your local store only. Record, for every document: title, source type, publisher,
edition/date, licence status, and the applicability metadata for each passage.
A passage without applicability metadata is stored, but it can never resolve a
conflict.

Do not commit imported material. `.gitignore` excludes `data/manuals/`,
`data/sources/`, `data/raw/` and all PDFs by default.
